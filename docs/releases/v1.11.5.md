N 계기판·'내 앱'·모든 설치기 **1.11.5**. 내비 빌드 번호가 달라도 설치되고, 네온 드라이브 데모 모드를 끌 수 있습니다.

| 기기 | 받을 파일 | 사용 |
| --- | --- | --- |
| Windows | `vn-installer-windows.zip` | 압축을 풀고 `N계기판설치.cmd` 더블클릭 → 창에서 [설치] (이전 창 설치기는 [업데이트] 단추가 뜹니다) |
| 맥 | `vn-installer-mac.zip` | 압축을 풀고 `N 계기판 설치.app` 실행 |
| 안드로이드 폰·태블릿 | `vn-installer-android.apk` | 설치 후 OTG 어댑터(USB-C → USB-A 암) + A-A 케이블로 차에 연결 |
| 리눅스 | `vn-installer-linux.zip` | `bash install.sh` |

바뀐 점
- 설치기(Windows·맥·리눅스·폰): 내비 빌드 번호가 검증한 `eng.vmadmin.20250902.081552`와 달라도 멈추지 않고, "주의: 검증한 빌드와 다른 빌드입니다" 경고만 띄운 뒤 설치합니다. 벨로스터 N 내비(`jsn_kr`)가 아니거나 API 17이 아니면 전처럼 설치하지 않습니다("지원하지 않는 내비입니다").
- 네온 드라이브: 다른 빌드의 내비에서 데모 모드를 꺼도 데모가 계속 돌던 문제를 고쳤습니다. 이제 빌드 번호와 상관없이 차량 값을 읽습니다. 수신 형식이 다르면 값을 버리고 `NO SIGNAL`로 표시합니다.
- 계기판: 같은 이유로 다른 빌드에서 읽지 않던 추가 차량 값(`hscan_mux`)도 읽습니다. 형식이 정확히 맞는 값만 씁니다.
- 메뉴 수정 도구(`scripts/menu_entry.py`): 빌드 번호가 다르면 경고만 합니다. 순정 APK·ODEX·프레임워크 해시는 여전히 모두 맞아야 진행합니다.

확인 범위
- 확인: 맥·리눅스 설치기 시험(다른 빌드 → 경고 후 설치, API 19 → 거부), 폰 설치 앱 시험(10개 상황), 호스트 단위 시험, Windows 설치기 시험(GitHub Actions).
- 미확인: 검증 빌드가 아닌 실차에서의 설치·계기판·네온 드라이브 동작(값이 나오는지, `NO SIGNAL`인지).
