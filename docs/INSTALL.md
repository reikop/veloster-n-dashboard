# 설치·실행·복귀

한국어·영어 선택과 업데이트 변경점은 [언어 안내](LANGUAGES.md)를 참고하세요. 버튼 문구는 선택한 언어에 따라 표시됩니다.

[English](INSTALL_EN.md) | **한국어**

**설치와 실행 바로가기 설정은 서로 다른 단계입니다.** APK 두 개를 설치해도 순정 홈에 ‘내 앱’이 자동으로 나타나지는 않습니다. 권장 순서는 설치 → ADB로 첫 실행 → v10의 [실행 바로가기](QUICK_ENTRY_ko.md) 활성화 → HOME에서 재실행 확인입니다. OEM 메뉴 수정은 바로가기를 사용할 수 없을 때 검토하는 선택 사항입니다.

아래는 **product `jsn_kr`, Android API `17`, incremental `eng.vmadmin.20250902.081552`**에 한정한 절차입니다. 새 설치 도구는 이 대상을 확인하며, 다른 빌드로 우회하는 옵션을 제공하지 않습니다. 메뉴 수정은 이 조건 외에도 해당 차량의 원본 APK·ODEX가 지원 원본과 일치해야 합니다. 다른 지역·연식·업데이트 버전의 호환성을 의미하지 않습니다.

2026-10-26에 설치 도구·문서를 보완했습니다. 이것은 새로운 실차 설치·냉간 재부팅 검증을 완료했다는 뜻이 아닙니다. N 계기판 v6는 다국어 UI 변경본으로 실차 검증 전이며, 이전 v5의 차량 데이터 처리 코드는 유지했습니다. ‘내 앱’ v10는 서명·호스트 검사만 마친 사전 배포로 실차·에뮬레이터 검증은 하지 않았습니다. 자세한 범위는 [배포 기록](RELEASE.md)을 참고하세요.

## 1. PC와 차량 준비

1. 차량을 정차하고 화면을 확인할 수 있는 상태에서 [ADB 연결 안내](ADB.md)를 따릅니다.
2. 개별 APK만 받지 말고 **최신 저장소 전체 또는 `v2026.10.26-i18n` 릴리스 묶음**을 내려받아 압축을 풉니다. PC 터미널의 현재 폴더를 `README.md`, `scripts/`, `apks/`가 있는 프로젝트 폴더로 옮깁니다. 최초 `v2026.10.23` 릴리스 ZIP에는 새 설치·메뉴 도구가 없습니다.
3. Python 3.9 이상과 Android SDK Platform-Tools의 `adb`를 준비합니다. 다음 명령은 PC에서 실행합니다. 예시는 macOS/Linux의 bash/zsh 문법입니다. Windows에서는 Python 명령을 `py -3`으로 바꾸고 `"$VN_SERIAL"` 대신 실제 일련번호를 직접 적을 수 있습니다. POSIX 변수 대입을 PowerShell에 그대로 붙여 넣지 마세요.

```sh
python3 scripts/verify_release.py
adb devices -l
VN_SERIAL='YOUR_DEVICE_SERIAL'
adb -s "$VN_SERIAL" shell getprop ro.product.name
adb -s "$VN_SERIAL" shell getprop ro.build.version.sdk
adb -s "$VN_SERIAL" shell getprop ro.build.version.incremental
```

`YOUR_DEVICE_SERIAL`은 `adb devices -l`에 표시된 본인 기기의 일련번호로 바꿉니다. 장치 상태가 `device`여야 하며 속성은 순서대로 `jsn_kr`, `17`, `eng.vmadmin.20250902.081552`여야 합니다. 장치가 없거나 `offline`·`unauthorized`이면 APK 설치보다 연결 문제를 먼저 해결합니다. 구형 adbd에 `adb shell -T`를 사용하지 않습니다.

## 2. N 계기판과 ‘내 앱’ 설치·업데이트

배포 APK는 이미 서명돼 있으므로 기본 설치에 Java·Android SDK 빌드 도구나 직접 컴파일은 필요하지 않습니다. Python과 ADB로 실행합니다.

```sh
python3 scripts/install.py --serial "$VN_SERIAL" --parked
```

도구가 실행마다 `private-backups/` 아래에 새로운 백업 폴더를 만들고 위치를 출력합니다. 이전 백업을 덮어쓰지 않습니다. 먼저 차량을 변경하지 않고 검사만 하려면:

```sh
python3 scripts/install.py --serial "$VN_SERIAL" --check
```

`--check`는 PC에 백업·점검 기록을 만들지만 차량에 설치하거나 앱을 실행하거나 바로가기 설정을 변경하지 않습니다.

`--parked`는 사용자가 정차 상태를 확인했다는 표시이며, 도구가 차량의 정차 여부를 감지한다는 뜻은 아닙니다.

이 단계는 배포 APK의 무결성과 대상 기기를 확인하고, 기존 앱이 있으면 APK를 새 백업 폴더에 보관한 뒤 N 계기판 v6와 ‘내 앱’ v10를 설치합니다. 업로드·설치 후 APK를 다시 읽어 확인하며, 구형 adbd의 종료 코드만으로 성공을 판단하지 않습니다. 오류로 중단되면 출력된 이유와 백업을 보존하고, 수동 삭제·강제 덮어쓰기로 우회하지 마세요. 두 앱 설치는 하나의 원자적 작업이 아니므로 두 번째 앱에서 실패했다면 첫 번째 앱은 이미 업데이트됐을 수 있습니다.

APK 백업은 **앱 설정·사용자 데이터 백업이 아닙니다.** 두 앱은 `allowBackup=false`이며 일반 ADB로 게이지·그래프·앱 목록 설정까지 복구한다고 보장하지 않습니다. 개인 백업 폴더를 GitHub나 공개 게시물에 올리지 마세요.

설치·읽기 검증이 성공하면 도구가 ‘내 앱’을 여는 요청까지 보냅니다. 순정 N 모드를 교체하거나 홈 메뉴를 수정하거나 바로가기를 자동으로 켜거나 내비를 재부팅하지 않습니다. **실행 요청 수락과 화면에 실제 표시되는 것은 다릅니다.** 아래 화면 확인까지 진행하세요.

## 3. 연결된 상태에서 처음 실행

설치 도구가 연 ‘내 앱’ 화면을 먼저 확인합니다. 화면을 닫았거나 직접 확인해야 한다면 설치 성공 후 다음 명령을 사용합니다.

```sh
adb -s "$VN_SERIAL" shell pm path com.veloster.carplayhub
adb -s "$VN_SERIAL" shell pm path com.veloster.dashboard
adb -s "$VN_SERIAL" shell am start -n com.veloster.carplayhub/.HubActivity
```

각 `pm path`에 `package:...apk` 경로가 출력되어야 합니다. ‘내 앱’ 화면에서 **N 계기판**을 누릅니다. 계기판만 직접 열려면:

```sh
adb -s "$VN_SERIAL" shell am start -n com.veloster.dashboard/.DashboardActivity
```

버튼 기능은 [내 앱 사용법](MY_APPS_ko.md)을 참고하세요. USB 디버깅 OFF·강제 재시작·시험 핫스팟은 설치 확인에 필요한 동작이 아닙니다. USB OFF와 재시작은 현재 PC 연결을 끊을 수 있습니다.

## 4. v10 실행 바로가기 설정과 화면 확인

1. ‘내 앱’ 위쪽의 **실행 바로가기 / Quick entry**를 누릅니다.
2. **가장자리 버튼 + 알림 / Floating + notification**을 선택하고 **저장 / Save**을 누릅니다. 기본값은 OFF이며 설치만으로 자동 활성화하지 않습니다.
3. HOME으로 돌아가 화면 가장자리의 작은 **앱** 버튼을 눌러 ‘내 앱’을 다시 엽니다. 버튼을 끌어 위치를 옮길 수 있습니다.
4. ‘내 앱’에서 **N 계기판**을 눌러 화면 전환과 수신값을 확인합니다. 미수신 값 `-`와 앱 설치 실패를 구분합니다.
5. **HOME → 작은 앱 버튼 → 내 앱 → N 계기판** 재실행이 실제 동작한 뒤 PC를 분리합니다. 이후 정차 상태의 정상 완전 재부팅 후에도 같은 진입과 수신을 따로 확인합니다.
6. 버튼 표시가 차단되면 서비스는 알림을 유지하고 오류를 표시합니다. 알림으로 ‘내 앱’을 실제 열 수 있는지 확인합니다. 알림도 순정 UI에서 열 수 없다면 아래 대체 경로가 필요합니다.

이 기능은 표준 Android 서비스·오버레이·알림을 사용하고 순정 메뉴를 수정하지 않습니다. 하지만 기기 권한과 UI에 따라 표시·접근이 제한될 수 있습니다. **설정 저장이나 서비스 시작만으로 실차 성공이라고 판단하지 말고 화면 터치로 재실행을 확인하세요.** 자세한 동작·끄기·복원 제한은 [실행 바로가기 안내](QUICK_ENTRY_ko.md)에 있습니다.

### 대체 경로: 기존 런처 또는 선택형 OEM 메뉴

호환 런처나 앱 목록이 있으면 그 경로를 사용해도 됩니다. v10 버튼과 알림 모두 접근할 수 없다면 [순정 메뉴 추가 절차](MENU_ENTRY_ko.md)를 검토합니다. 이 수정은 모든 사용자에게 필요한 단계가 아니며, 지원 원본 APK·ODEX와 일치하는 빌드에만 적용합니다.

메뉴 도구는 사용자 차량에서 확보한 원본을 검사한 뒤 로컬에서 수정본과 복구본을 만듭니다. 제조사 APK를 공개 배포하지 않습니다. 지원 원본과 다르면 중단하며 다른 차량용 수정본을 설치하지 않습니다. 단순 재설치로 순정 홈 아이콘이 생기지는 않습니다.

## 케이블 분리·재부팅 후 실행

앱이 실행된 뒤 차량 데이터는 내비 내부 서비스에서 받으므로 PC 케이블이 계속 연결되어 있을 필요는 없습니다. 케이블을 빼거나 정상 재부팅했다고 앱을 다시 설치할 필요도 없습니다. **v10에서 켜 둔 바로가기 서비스만 부팅 후 복원을 요청하며, 계기판·내 앱 화면은 자동으로 열지 않습니다.** 버튼이나 알림을 눌러 수동으로 엽니다. 강제 종료했거나 기기 정책이 차단하면 앱을 직접 다시 열어야 할 수 있습니다. OFF를 선택했다면 복원을 요청하지 않습니다.

기존 OEM 메뉴 진입점이 있는 연구 차량에서 확인한 경로는 다음과 같습니다. v10 바로가기를 사용할 수 있다면 이 메뉴 수정은 필수가 아닙니다.

1. 부팅이 끝나 홈 메뉴를 조작할 수 있을 때까지 기다립니다.
2. **홈(HOME) → 전체 메뉴 → 2페이지 → 정보 → 내 앱**을 엽니다.
3. **N 계기판**을 누릅니다. 순정 N 모드 안의 옛 `N 계기판` 버튼은 현재 독립 앱의 실행 경로가 아닙니다.

이 경로는 별도 OEM 메뉴 수정 후 2026-10-20에 화면 터치로 확인했습니다. 메뉴 위치·정렬은 기기 상태에 따라 달라질 수 있습니다. 이번 도구 공개가 v5의 냉간 재부팅·장시간 수신 또는 v10 바로가기 실차 복원 검증을 대신하지 않습니다. 처음 구성한 차량에서는 정차 상태에서 정상 종료·재부팅 후 같은 메뉴 경로와 값 수신을 따로 확인해야 합니다.

바로가기와 메뉴 모두 사용할 수 없다면 PC를 다시 연결하고 위 3단계 명령으로 실행할 수 있습니다. [실행 바로가기](QUICK_ENTRY_ko.md)의 설정·오류를 먼저 확인하고 필요하면 선택형 [메뉴 추가 문서](MENU_ENTRY_ko.md)를 참고하세요. 메뉴가 없어도 `pm path`에 경로가 나오면 설치된 상태입니다. 즉시 삭제하거나 재설치하지 마세요.

## 증상과 오류 구분

| 증상 | 다음 확인 |
| --- | --- |
| 설치 성공인데 ‘내 앱’ 아이콘이 없음 | 위 3단계 ADB 직접 실행 후 [v10 바로가기](QUICK_ENTRY_ko.md) 설정·화면 확인 |
| `pm path`에 패키지 경로가 없음 | 대상 일련번호와 설치 도구 결과 확인 |
| ‘내 앱’은 열리지만 계기판 실행 실패 | `pm path com.veloster.dashboard`와 실행 오류 확인 |
| 앱이 열리지만 추가 값이 `-` | 정확한 지원 빌드·시동 상태·서비스 준비·현재 수신·60초 만료 확인. ECU 요청으로 채우지 않음 |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | 기존 APK를 보존하고 중단. 기존 앱을 자동 삭제하거나 다시 서명해 우회하지 않음 |
| `INSTALL_FAILED_MISSING_SHARED_LIBRARY` | 필요한 OEM `automotive` 라이브러리가 없음. 다른 기기용 프레임워크를 복사하는 해결법은 미제공 |
| `INSTALL_FAILED_VERSION_DOWNGRADE` | 더 높은 버전이 설치됐을 수 있음. 아래 복귀 제한 확인 |
| 저장공간 부족 | 설치 도구 결과와 이번 작업의 임시 파일 확인. 시스템 앱·순정 데이터 임의 삭제 금지 |
| ADB에도 기기가 안 보임 | [USB 연결 안내](ADB.md)의 열거·모드·케이블 순서 확인 |

## 고급 복귀·제거

문제가 생기면 먼저 **독립 계기판만** 정지할 수 있습니다. 순정 N 모드는 별도 패키지입니다.

```sh
adb -s "$VN_SERIAL" shell am force-stop com.veloster.dashboard
```

`scripts/install.py`와 고급 명령 `menu_entry.py install-apps`는 현재 배포본 v6/v10 설치용입니다. v3 복귀나 임의 백업 APK 설치 옵션으로 해석하지 마세요. 고급 작업에서 백업 위치를 직접 지정하려면 `python3 scripts/menu_entry.py install-apps --serial "$VN_SERIAL" --backup private-backups/apps-01 --parked`를 사용할 수 있으며 해당 폴더는 아직 존재하지 않아야 합니다. 이 고급 명령은 기본 설치 도우미의 자동 화면 열기와는 별개입니다. 메뉴 수정 복구는 [메뉴 문서](MENU_ENTRY_ko.md)의 별도 복구 절차를 사용합니다. 계기판을 제거하는 것으로 순정 메뉴 수정이 복구되지는 않습니다.

같은 서명·같거나 높은 버전인 본인 백업 APK는 수동 `push` → 업로드 파일 재조회·해시 비교 → `pm install -r` → 설치 파일 재조회·해시 비교 방식으로 복귀할 수 있습니다. 매번 새로운 임시 파일명과 백업 폴더를 사용하고 각 단계의 성공을 확인해야 합니다. 기존 임시 파일에 이어서 설치하거나 원본 백업을 덮어쓰지 마세요.

v3는 v5보다 낮은 버전이므로 `pm install -r`로 거절될 수 있습니다. `-d` 옵션 지원 및 v5 설정을 유지한 v3 실행은 이 공개 패키지에서 실차 검증하지 않았습니다. 자동 다운그레이드를 제공하지 않습니다.

**설정 소실을 받아들이고 독립 앱을 새로 설치하기로 선택한 경우에만**, 백업을 확보한 뒤 `adb -s "$VN_SERIAL" shell pm uninstall com.veloster.dashboard`로 제거하고 서명된 v3 APK(`apks/rollback/N-Dashboard-v3-API17.apk`)를 별도 수동 설치할 수 있습니다. 제거하면 저장한 게이지·그래프 설정이 지워집니다. v3 설치 후에도 홈 진입점과 동작 확인이 필요합니다.

프로젝트 제거 대상은 독립 패키지 `com.veloster.dashboard`, `com.veloster.carplayhub`입니다. 메뉴 추가 도구까지 사용했다면 먼저 해당 메뉴 복귀 절차를 확인하세요. ‘내 앱’을 지우기 전 필요한 USB/무선 상태를 복구합니다. 앱 제거가 기기 설정이나 과거 순정 N 모드 수정본까지 자동 복구하지는 않습니다.
